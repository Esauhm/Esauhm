<h3>🏗️ Architecture and design</h3>
<ul>
  <li><strong>Clean Architecture:</strong> separation between <code>Domain</code>, <code>Application</code>, <code>Infrastructure</code>, and <code>API</code>.</li>
  <li>Controlled dependency direction between projects.</li>
  <li>Dependency injection.</li>
  <li>Repository Pattern and Service Layer.</li>
  <li>DTOs for requests and responses.</li>
  <li>Interfaces that decouple application logic from infrastructure.</li>
  <li>Clear separation of responsibilities.</li>
</ul>

<h3>🏛️ Domain and business rules</h3>
<ul>
  <li>Domain entities with encapsulated state and behavior.</li>
  <li>Relationship validation between areas, consultants, and packages.</li>
  <li>Logical deactivation of records.</li>
  <li>Controlled reactivation of areas, consultants, and packages.</li>
  <li>Automatic package cost calculation.</li>
  <li>Automatic consultant area and rate selection.</li>
  <li>Historical rate preservation through <code>TarifaHoraAplicada</code>.</li>
  <li>Active entity validation before operations are executed.</li>
</ul>

<h3>🌐 REST API</h3>
<ul>
  <li>API built with ASP.NET Core Web API.</li>
  <li>Versioned endpoints using <code>/api/v1</code>.</li>
  <li>Controllers separated by module.</li>
  <li>Appropriate HTTP status codes.</li>
  <li>Consistent response contracts.</li>
  <li><code>PATCH</code> endpoints for reactivation flows.</li>
  <li>Interactive documentation with OpenAPI and Swagger UI.</li>
</ul>

<h3>🔐 Security</h3>
<ul>
  <li>JWT Bearer authentication.</li>
  <li>Signed tokens.</li>
  <li>Issuer, audience, and expiration validation.</li>
  <li>Identity and role claims.</li>
  <li>Role-based authorization using <code>Admin</code> and <code>User</code>.</li>
  <li><code>401 Unauthorized</code> and <code>403 Forbidden</code> responses.</li>
  <li>Hashed passwords.</li>
  <li>Sensitive configuration through environment variables and User Secrets.</li>
</ul>

<h3>✅ Validation and error handling</h3>
<ul>
  <li>Request validation with FluentValidation.</li>
  <li>Additional business validation inside application services.</li>
  <li>Global exception handling.</li>
  <li>Error responses using <code>ProblemDetails</code>.</li>
  <li>Handling of <code>400</code>, <code>404</code>, <code>409</code>, <code>422</code>, and <code>500</code> responses.</li>
</ul>

<h3>🗃️ Persistence and database</h3>
<ul>
  <li>Entity Framework Core as ORM.</li>
  <li>SQL Server 2022.</li>
  <li>Centralized DbContext.</li>
  <li>Separate entity configurations.</li>
  <li>Repositories for data access.</li>
  <li>Database migrations.</li>
  <li>Relationships and foreign keys.</li>
  <li>Constraints and unique indexes.</li>
  <li>Idempotent seeders.</li>
  <li>Initial data for users, specialization areas, consultants, and packages.</li>
</ul>

<h3>🛡️ Data consistency and concurrency</h3>
<ul>
  <li>Optimistic concurrency using SQL Server <code>rowversion</code>.</li>
  <li><code>RowVersion</code> in areas, consultants, and packages.</li>
  <li>Original version submitted during update operations.</li>
  <li>Detection of records modified by another user.</li>
  <li><code>409 Conflict</code> response for stale versions.</li>
  <li>Protection against lost updates.</li>
</ul>

<h3>⚡ Performance</h3>
<ul>
  <li>Pagination executed directly in SQL.</li>
  <li>Use of <code>Skip</code> and <code>Take</code>.</li>
  <li><code>AsNoTracking</code> for read-only queries.</li>
  <li>Direct projections from Entity Framework Core queries to DTOs.</li>
  <li><code>IMemoryCache</code> for reports.</li>
  <li>Tracked queries only when an update follows.</li>
  <li>Asynchronous methods.</li>
  <li><code>CancellationToken</code> propagation.</li>
</ul>

<h3>📊 Reports</h3>
<ul>
  <li>Packages grouped by specialization area.</li>
  <li>Consultants ranked by billing.</li>
  <li>Optional filters.</li>
  <li>Ascending and descending sorting.</li>
  <li>Pagination.</li>
  <li>Totals, averages, and aggregate metrics.</li>
  <li>Temporary cache to reduce repeated queries.</li>
</ul>

<h3>📝 Logging and monitoring</h3>
<ul>
  <li>Logging through <code>ILogger</code>.</li>
  <li>Important operation logging.</li>
  <li>Error and relevant event logging.</li>
  <li>Process health check through <code>/health/live</code>.</li>
  <li>API and database readiness check through <code>/health/ready</code>.</li>
</ul>

<h3>🧪 Automated testing</h3>
<ul>

<h3>🐳 Containers and infrastructure</h3>

  <li>Execution with a non-root user.</li>

  <li>Environment variables.</li>

  <li>Startup dependency controlled through health checks.</li>
  <li>Persistent SQL Server volume.</li>
  <li>Separate Development and Testing environments.</li>
